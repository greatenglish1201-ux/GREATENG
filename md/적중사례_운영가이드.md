# 📌 적중사례 시스템 운영 가이드 (GREATENG)

> **다음 시험부터 이 문서 하나만 보고 똑같이 하면 됩니다.**
> 파일 3개가 맞물려 돌아가며, **평소엔 `results.js` 한 파일만** 고치면 세 곳(적중사례 페이지·메인 요약)이 자동 갱신됩니다.

---

## 1. 구조 (파일 3개의 역할)

| 파일 | 역할 | 언제 수정 |
|---|---|---|
| `results.js` | **데이터 저장소.** 시험별 적중 결과 객체 배열(`RESULTS`) | **시험 볼 때마다 여기만 수정** |
| `results.html` | 적중사례 전체 페이지. `results.js`를 읽어 자동 렌더(정렬·요약·카드·펼치기) | 거의 안 건드림 (표시 방식 바꿀 때만) |
| `main.html` | 메인. 하단에 요약 섹션(최근 2개 시험 + KPI), 네비에 "적중사례" 링크 | 거의 안 건드림 (이미 삽입 완료) |

`main.html`과 `results.html`은 **둘 다 같은 `results.js`를 읽습니다.** 그래서 데이터는 한 곳에만 있습니다.

---

## 2. 다음 시험 추가하는 법 (평상시 작업 — 이것만 하면 끝)

`results.js`의 `const RESULTS = [` **바로 아래(맨 앞)**에 아래 한 덩어리를 붙여넣습니다. (최신 시험이 위로 가도록 맨 앞에 추가)

```js
  {
    school: "학교명",                    // 예: "포항제철고"
    exam: "학년 학기 시험 (과목)",        // 예: "2학년 1학기 기말 (영어Ⅰ)"
    date: "2026-09-15",                  // 시험일 YYYY-MM-DD (정렬 기준, 정확히)
    total: 28,                           // 분모 문항수
    hit: 6,                              // 적중 문항수
    hideRate: true,                      // (선택) 아래 3번 참고 — 필요없으면 이 줄 삭제
    basis: "분모 산정 기준 문구",          // 카드에 그대로 표기됨 (정직 표기)
    detailUrl: "",                       // 상세분석 페이지 있으면 "analysis/파일.html", 없으면 ""
    blogUrl: "",                         // 블로그 후기 있으면 링크, 없으면 ""
    hits: [
      { topic: "지문 소재", predicted: "예상 유형", actual: "실제 출제 유형" },
      { topic: "...",       predicted: "...",     actual: "... (완전 적중)" }
      // 완전 적중이면 actual 끝에 " (완전 적중)" 붙이기 — 카드에서 강조됨
      // 상세 없으면 hits: [] (빈 배열) — 카드 요약만 표시됨
    ]
  },
```

저장 후 **GitHub Desktop으로 `results.js`만 커밋**하면 끝. 적중사례 페이지와 메인 요약이 같이 갱신됩니다.

---

## 3. `hideRate` — 언제 쓰나 (중요)

시험마다 **분모 기준이 다릅니다.** 어떤 시험은 "전체 문항", 어떤 시험은 "예상문제와 겹친 지문만"을 셉니다.
- 분모가 전체 문항이라 **적중률 %가 자연스러우면** → `hideRate` 줄 삭제 (%로 표시됨)
- 분모 기준이 달라서 **% 숫자가 낮게/이상하게 보이면** → `hideRate: true` 추가

`hideRate: true`이면:
1. 카드에 % 대신 **"지문 N개 적중"**으로 표기
2. 상단 **평균 적중률 계산에서 제외** (기준 다른 시험이 평균을 왜곡하지 않음)

예) 제철고1(6/28=21%)은 "예상문제 동일지문 6개"만 센 것이라 `hideRate: true` → "지문 6개 적중"으로 표기, 평균에서 빠짐.

## 4. 배포 (GitHub Desktop 커밋 순서)

**이미 세팅 끝났으면 평소엔 `results.js`만 커밋.** 최초 1회 세팅 시:

1. `results.js` — 레포 루트에 업로드
2. `results.html` — 레포 루트에 업로드
3. `main.html` — 레포 루트에 업로드 (요약 섹션·네비 링크·스크립트가 이미 삽입된 완성본)
4. (상세 분석 페이지가 있으면) `analysis/파일.html` — analysis 폴더에 업로드

커밋 후 확인: `main.html` 접속 → 하단 "내신 적중 현황" 섹션에 KPI·카드 뜨는지 / 네비 "적중사례" 클릭 → `results.html` 열리는지.
