> 최종 갱신: 2026-07-07

## 1. GAS 작업 ⚠️

GAS(Google Apps Script) 수정 시 **반드시** 다음을 지킵니다:

1. **전체 백업 먼저** — 수정 전 코드 전체를 별도 보관
2. **일부만 붙여넣기 금지** — 항상 전체 코드로 교체
3. **저장 후 '새 버전 배포'** — 기존 배포 덮어쓰기 아님
4. **어느 GAS인지 먼저 확인** — 단어시험 / 숙제점검 / index 로그인

## 2. passages.js 보호 규칙

`teacher.html`의 `upsertPassages` / `buildOutput` / `saveMainToGitHub`에서 **기존 필드를 삭제하거나 변경하지 말 것.**

## 3. 저작권

| 자료 | 취급 |
|---|---|
| 학교 기출 복원본 | 저작권은 해당 학교에 있음. **학원 내부 분석용만.** 온라인 게시 금지 |
| 기출 원문 포함 문서 | 대면 상담 전용 (상담용 HTML, 학부모 안내 docx, 문제대조 docx) |
| 자체 예상문제 | 공개 가능. 블로그 게시 시 예상문제만 노출 |

**블로그 게시 전 확인**: 기출 원문 문구가 섞였는지 검색으로 확인. (예: 기출에만 있는 특정 문장 4~5개를 골라 문서에 없는지 grep)

## 5. 적중 발표 원칙

- **분모를 명확히**: "○○교재 범위 내 N문항 적중"
- 범위 밖(외부지문·모의고사) 문항이 분모에 섞이면 수치가 왜곡됨
- 분모 기준이 다른 시험은 results.js에 `hideRate: true` → % 대신 "지문 N개 적중" 표기 + 평균 계산 제외
- 미적중분도 정직하게 설명 (이동고3 사례: "실제 범위가 준비 범위보다 넓었다")

## 6. 적중사례 페이지 갱신

**평상시엔 `results.js` 한 파일만 수정하면 됩니다.**

- `results.js` — 데이터. 시험 객체를 `RESULTS` 배열 맨 앞에 추가
- `results.html` — 자동 렌더 (학교별 필터 버튼도 자동 생성)
- `main.html` — 하단 요약 섹션 (최근 2개 + KPI)

시험 객체 형식:
```js
{
  school: "학교명", exam: "학년 학기 시험 (과목)", date: "YYYY-MM-DD",
  total: 28, hit: 6,
  hideRate: true,            // 선택 — 분모 기준이 다를 때
  basis: "분모 산정 기준 문구",
  detailUrl: "", blogUrl: "",
  hits: [{ topic:"소재", predicted:"예상 유형", actual:"실제 유형 (완전 적중)" }]
}
```

## 7. 세션 시작 시

**출제 작업은 [출제절차.md](출제절차.md)의 체크리스트·프롬프트 템플릿을 따릅니다.**


**출제·분석 작업을 시작할 때 해당 학교 md 파일을 먼저 올릴 것.**
(자동으로 읽히지 않으므로 직접 첨부해야 적용됩니다.)

- 제철고1 작업 → `docs/제철고1.md`
- 제철고3 작업 → `docs/제철고3.md`
- 제철중3 작업 → `docs/제철중3.md`
- 이동고3 작업 → `docs/이동고3.md`

## 8. 시험 후 갱신 절차

1. 기출 복원 → 적중 분석
2. 해당 학교 md **2부 시험 기록**에 블록 추가
3. 새로 발견한 출제 원리가 있으면 **1부 해당 유형 항목 수정**
4. `results.js`에 시험 객체 추가
5. 기출DB 시트에 문항별 데이터 반영
